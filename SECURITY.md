# Политика безопасности

## Поддерживаемые версии

| Версия | Исправления безопасности |
| ------ | ------------------------ |
| 0.1.x  | да                       |

## Как сообщить об уязвимости

**Не создавайте публичную задачу (Issue) с описанием уязвимости.**

1. Откройте на GitHub вкладку **Security → Report a vulnerability** (приватное сообщение мейнтейнерам). Если она недоступна — напишите владельцу репозитория через контакт в его профиле и попросите приватный канал.
2. Приложите: что уязвимо, шаги воспроизведения, версию/коммит, возможное влияние. Реальные пароли, токены и данные игроков в отчёт не включайте.

Мы стараемся подтвердить получение в течение 7 дней и сообщить план исправления в течение 30 дней. Исправление выходит вместе с записью в `CHANGELOG.md`; автор отчёта по желанию указывается в благодарностях.

## Что считаем уязвимостью

Обход аутентификации или ролей, доступ к режиму бога без владельца, чужие данные в ответах API, инъекции и XSS, обход идемпотентности/блокировок, ведущий к дублированию ресурсов, утечка секретов.

Не считаем: перебор паролей с игнорированием блокировок при выключенных лимитах в режиме разработки, отсутствие HTTPS на `localhost`, проблемы во временных туннелях (`pnpm share`).

## Правила для эксплуатации

- Секреты (`JWT_ACCESS_SECRET`, `GOD_MODE_PASSWORD_HASH`, `GOD_MODE_TOTP_SECRET`) хранятся только в окружении, не в git. В production сервер не запускается с заглушкой `JWT_ACCESS_SECRET`.
- Режим бога по умолчанию выключен (`GOD_MODE_ENABLED=false`); включайте только с паролем и лучше с TOTP.
- Ставьте HTTPS-терминацию перед nginx/API. Заголовок CSP в поставляемой конфигурации nginx работает в режиме Report-Only.

Технический обзор защиты — [`docs/SECURITY.md`](docs/SECURITY.md); режим бога — [`docs/GOD_MODE.md`](docs/GOD_MODE.md).
